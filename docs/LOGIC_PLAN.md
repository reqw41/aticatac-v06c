# Логика и ход игры: план (с 25.10.2026)

Решение владельца: логика CPC переносится через **JS-модель** (сверка с CPC по шагам), потом —
**i8080 с оптимизацией** (сверка с JS-моделью). Отрисовка — своя (docs/PROTO.md: комнаты, спрайты без XOR).

## Этапы
0. **Эталон CPC.** Своя модель CPC 6128 на JS (`tools/cpc6128.js`: Z80 из Indy с исправленным INI/IND,
   банки C0/C4..C7, PPI/PSG-клавиатура, 6 прерываний на кадр, такты по 4). Игра грузится из сборки
   (build/cpcnew) без дискеты. `tools/cpc_trace.js <сценарий>` пишет шаги в build/golden/*.json.gz.
1. **JS-модель** (src/model/): функции по подпрограммам CPC, память — в раскладке CPC (страницы 0, 1, 5),
   вывод не моделируется. Сверка по шагам с эталоном (tools/model_run.js).
2. **i8080** по модулям: тот же порядок, сверка с JS-моделью покомандно/по шагам; оптимизация под 8080
   (без IX/IY, данные в удобной раскладке — когда сверка зелёная).
3. **Сборка игры на Векторе:** логика + комнаты (proto/room.asm) + спрайты без XOR (proto.asm -DOVR) +
   клавиатура/джойстик + звук.

## Шаг и состояние
- Шаг = вызов задачи состояния из главного цикла (`current_game_state`: game_tasks / falling_tasks /
  end_tasks / menu_tasks). На CPC 1 кадр на шаг (50 Гц).
- Состояние = страница 0 (код и переменные 0x0000–0x3FFF; самомодифицируемые места — тоже), банк
  предметов (стр. 1), банк комнат (стр. 5). Экраны, графика (стр. 4, 7) и звук (стр. 6) — нет.
- **Адреса прерывания** — всё, что пишет обработчик (клавиатура, часы, heartbeat, звук, экраны);
  их нет в сравнении. Их чтения игрой посреди шага (клавиатура опрашивается ~3.3 мс после начала шага)
  записаны в эталоне по порядку (`rd`) — модель берёт значения из этой очереди.
- Случайность: `ld a,r` — значения в эталоне (`r`); RANDOM_IN_A дальше детерминирован.
- Звук: номера эффектов на входе play_sfx (`sfx`) — сверяются.

## Сценарии (research/scenarios)
- s0_random — случайные клавиши (за 3000 шагов из комнаты 0 не выходит).
- Нужны: политика «к двери» (обход комнат), смерти, ключи и двери, люки (падение), еда, боссы
  (Дракула, мумия, Франкенштейн, горбун, дьявол), курица, победа. Покрытие — по подпрограммам.

## Найдено
- Z80.js (Indy): INI/IND брали порт по B после уменьшения — клавиатура CPC не читалась. Исправлено в
  tools/vendor/Z80.js.

## Этап 1 — состояние на 25.10.2026 (ночь)
JS-модель (src/model/, ~1300 строк) повторяет всю логику игры: game_tasks целиком, смена комнаты
(draw_room без вывода), двери и люки, падение (falling_tasks), враги и боссы, оружие, герой (жизни,
появление/исчезновение, могилы), здоровье, еда, предметы и карманы, счёт, часы, пауза, конец игры
(экран итогов). Не смоделировано: меню и переход из итогов в меню (у Вектора меню своё), вывод, звук
(сверяются номера эффектов).

Проверка — `node tools/shadow.js <сценарий>`: каждая смоделированная подпрограмма на каждом вызове против
Z80 на том же состоянии (со старта машины, включая init_* при начале игры). Сценарии research/scenarios:
s0_random, s1_explore, s2..s4_explore (по 15 000 шагов), s5_bosses (телепорты в комнаты боссов),
s6_left/s7_right (другие герои), s8_mummy_end (мумия, пауза, финальная комната) — **все без расхождений**.
Покрытие кода — `node tools/coverage.js <сценарии>`; не пройдены ветки «мумия прыгает», «горбун идёт к
предмету», move_frankie (мёртвый код).

Тонкости, найденные по дороге: прерывание ровно на входе в отслеживаемое место (вызов, ld a,r, звук) —
считать событие только если команда выполнилась; continue_player_transition входит переходом и выходит
через конец game_tasks — проверяется только в составе шага.

Сценарии: `pokes` (запись в память перед шагом, "@метка" — значение переменной), политика explore
(двери, предметы с огнём 2, люки, выстрелы), выбор героя — клавиши в `menu`.

Прогон модели без процессора — `node tools/model_run.js build/golden/*.json.gz` (снимок `first`, очереди
`rd`/`r`, телепорты `pk`): все 8 эталонов без расхождений (меню не моделируется — его шаги берутся из
эталона). Эталоны пересобираются `node tools/cpc_trace.js research/scenarios/<имя>.json` (~10–17 с).

## Дальше — этап 2 (i8080)
Логика на 8080 по модулям, сверка с JS-моделью на тех же сценариях (раскладка памяти Вектора своя —
нужна карта адресов «переменная CPC ↔ Вектор» для сравнения).

## Этап 2 — состояние на 25.10.2026 (ночь)
Логика на i8080 (src/i8080/*.asm, ~7 КБ кода, `python3 tools/mk80sym.py && python3 tools/mk80data.py`,
`cd src/i8080 && ../../tools/sjasmplus --i8080 logic.asm --sym=../../build/l80/logic.sym`) — все модули
модели. Сверка `node tools/lock80.js build/golden/*.json.gz`: JS-модель идёт непрерывно с фиксированным
вводом на шаг (последнее значение каждого адреса прерывания), общей очередью ld a,r, с новой игры
(select_game) и падениями раз в 2000 шагов; каждая подпрограмма i8080 с одноимённой меткой проверяется на
каждом вызове на зеркале памяти (вложенные — на чистом зеркале). Все 9 эталонов (~80 тыс. шагов) — **без
расхождений**.

Раскладка на время сверки: страница 0 CPC по своим адресам (C_имя из build/l80/cpcsym.inc), банк комнат
0x4000, еда FOOD80 = 0x3800 (указатели на неё переводятся), item_wh (ширина/высота предметов), код 0xE000,
служебное сверки 0xDF00 (очередь ld a,r, журнал звуков). Банков нет. Индексная адресация CPC — код на
каждый экземпляр (USPR, WHIT, PVB) для горячих мест и указатель ixp для остального.

Цена (такты Вектора, без оптимизации): шаг игры в среднем ~6,7–7,4 тыс. (11–12 % кадра), смена комнаты
~200 тыс. (3,4 кадра: сетка столкновений 576 клеток ×2 прохода), новая игра ~290 тыс. (init_doors 274 тыс.).
Самое дорогое в шаге: move_player ~3 тыс. (6 углов по 300), check_weapon_hit ~0,5 тыс., 4 × update_sprite.

## Дальше — этап 3 (игра на Векторе)
Логика + комнаты (proto/room.asm) + спрайты без XOR (proto.asm -DOVR) + клавиатура/джойстик + своя

## Этап 3 — первая играбельная сборка (25.10.2026, ночь)
`tools/build_game.sh` -> build/game/aticatac.r0m (64 КБ с 0x0000) + build/game/aticatac.edd (квазидиск 256 КБ).
Emu80: `Emu80qt --platform vector --edd build/game/aticatac.edd --run build/game/aticatac.r0m`.
Стенд: `node stand/vec/gamerun.js <кадров> <каталог> "кадр:клавиши,..."` (снимки каждые 50 кадров для
stand/vec/shot.py; PROF=1 — профиль, SPTRACE=1 — порча SP, TRACE=1 — выход за код, PATH1=1 — путь с загрузки).

Устройство (src/vec): game.asm — образ: страница 0 CPC (данные логики по своим адресам) + правки указателей
на графику (build/game/patch.inc), еда FOOD80, банк комнат 0x4000; код и данные — в свободных участках
(tools/layout.py по build/l80/holes.json из tools/holes.js: исполнявшийся код Z80, не тронутый логикой как
данные). main.asm — запуск, шаг 50 Гц по ВИ53 (без прерываний), клавиатура (стрелки, пробел — огонь,
Z — взять/бросить), часы и heartbeat как прерывание CPC, события вывода. spr.asm — 6 объектов XOR из потока
квазидиска (tools/mkgame.py: 109 кадров, 4 фазы). roomdraw.asm — комната (из proto/room.asm), ключи, еда.

Работает (стенд, 600 кадров): комната, рыцарь ходит, враги рождаются и движутся, двери переключаются;
47,8 шага/с. Нет: панели (счёт, часы, курица, жизни, карманы), роста/исчезновения героя (невидим),
туннелей падения, звука, меню и выбора героя (рыцарь), привязки к лучу (мерцание), джойстика; подбор
предмета перерисовывает всю комнату; самостоятельного образа без .edd (MiSTer).

## Этап 3 — шаги после уроков других портов (25.10.2026, docs/LESSONS.md)
1. **Часы кадра и потеря прерываний.** ISR по 0x38: счётчик 0 ВИ53 в режиме 0 (перезарядка FFFF), счёт
   кадров, опрос клавиатуры в гашении. Главный цикл: ждать новый кадр (EI), опоздали — один догоняющий шаг
   логики без вывода; события вывода копятся после каждого шага (collect_events / apply_events).
   di_guard перед выводом под DI. Стенд gamerun.js теряет прерывание под DI (окно 64 такта).
2. **Спрайты без мерцания.** На чёрном полу (карта фона комнаты из mkgame.py + отметки рисуемых предметов)
   и без касания других объектов — замещение на месте (новая рамка целиком, нули на уходящих краях);
   иначе XOR, как CPC (XOR-стирание верно для обоих способов). Объекты — по лучу (BEAM_W = 42):
   разрывы 0,3 % обновлений, ~42 шага логики/с. Гейт -DECHK: после N шагов стереть всё — экран = фон.
3. **Сверка боевого образа** — `node stand/vec/shipcheck.js <кадров> "<клавиши>"`: настоящий aticatac.r0m,
   на каждом шаге JS-модель той же задачей (ввод — как у игры, случайные — из её ldar); сравнение всех
   записанных адресов страницы 0 CPC, банка комнат, еды (кроме наших кусков). 1435 шагов — 0
   расхождений; негативный контроль SHIPBREAK=1 — красный. «Сверено 0» — провал.

Гейты перед коммитом игры: tools/build_game.sh (падает на ошибках), shipcheck (0), ECHK (0 отличий),
gamerun (доля разрывов, шагов/с), lock80 и model_run при правках логики/модели.
